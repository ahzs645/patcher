# Patch library

SVG patch art grouped by organization, for Patcher and for any app that embeds it.

```
library/
  orgs.json                   which organization each design belongs to (edit this)
  manifest.json               generated: sectors → organizations → patches, and the shared parts
  <org>/<id>.svg              the patch, with references to what it shares
  <org>/previews/<id>.webp    a small preview
  shared/<name>-<hash>.svg    a shared block: a crest or coat of arms several patches carry
  shared/paths-<hash>.json    shared path outlines, bundled by the patches that use them
```

Everything except `orgs.json` and this file is generated by `npm run library:import`. Don't edit it by
hand, because the next import replaces it.

## Where the patches come from

The **BC Forestry Patch Atlas** snapshot: the atlas site's own "Entire codebase" ZIP, shared on
[Google Drive](https://drive.google.com/file/d/1FttYbiCfmrQW4TbvcDD7lpVG9Y-gRzs4/view). The import reads its
277 reconstructions (`dist/assets/reconstructions.json` plus each SVG and WebP preview) and nothing else. It
does not read the source photographs, the template library or the registers. `manifest.json` records the
snapshot's SHA-256, and every patch keeps its atlas id, medium, quality, limitations and a link to its
source photograph.

They are reference-based vector reconstructions, not authenticated issue artwork. Fonts, thread colours and
fine embroidered detail are interpreted. Each patch's `limitations` says what is uncertain.

## Refreshing it

```bash
npm run library:import                         # downloads the snapshot (cached in .cache/)
npm run library:import -- --zip path/to.zip    # or use a copy you already have
npm run library:import -- --drive <id or URL>  # or a newer snapshot on Drive
```

Behind an HTTP proxy, prefix the command with `NODE_USE_ENV_PROXY=1`. The import refuses any SVG that has
scripts, event handlers, `foreignObject` or external references. It lists any design that no organization
claims, which are filed under `unsorted`.

## Shared parts

The drawings repeat a lot. The Conservation Officer Service crest (4.8 MB) is in three patches, and
the modern coat of arms is in seventeen. The same outlines also come back recoloured or moved. So the
import stores each repeated thing once, and the library is 13.2 MB instead of 34 MB:

- **Blocks.** When the same bytes sit inside a `<g>` in two or more places, they move to
  `shared/<name>-<hash>.svg`. The `<g>` stays in each patch with a placeholder,
  `<g data-shared="ID"/>`, inside it. A block can hold other blocks.
- **Path outlines.** A long `d="…"` that recurs with other colours or positions moves to a JSON
  bundle, and the attribute becomes `d="@ID"`. Outlines are bundled by exactly the patches that use
  them, and only when that group shares at least 4 KB. A patch therefore never downloads outlines it
  doesn't draw: opening one costs at most 3% more than its original file, in 1 request (median) to
  7 (max). Shared crests then come from cache.

Only exact bytes move. Joining a patch with its parts (`src/library-join.js`) gives back the atlas's
file byte for byte. The manifest records each patch's SHA-256 (the atlas's own `vectorSha256`) and the
blocks and bundles it needs, so a loader can fetch them all at once.

Every import ends by joining all 277 patches back from disk and comparing them with the snapshot. To
check again at any time:

```bash
npm run library:verify             # joined patches against the manifest's SHA-256
npm run library:verify -- --source # and file by file against the atlas snapshot
```

A stored `<org>/<id>.svg` is not the whole drawing on its own, so don't serve it directly. Load it with
`loadPatchSvg` (below), or join it with `joinSvg`.

## Grouping by organization

The atlas's own `affiliation` is coarse: half the designs are "Other". `orgs.json` splits them into
organizations (BC Sheriff Service, BC Corrections, Highways and Motor Vehicles, BC Hydro, …) and groups
those into sectors. Organizations are tried in order and the first match wins:

```json
{ "id": "bc-sheriff-service", "name": "BC Sheriff Service", "sector": "justice",
  "match": { "family": ["^sheriff", "^deputy-sheriff-"] } }
```

`family` and `label` are case-insensitive regular expressions tested against the atlas design. `affiliation`
matches the atlas's affiliation exactly. Put specific rules above broad ones (BC Wildfire Service sits above
the catch-all `"affiliation": ["Forestry"]`). Then re-import.

## Using it from code

In a Vite app, `patcher/library` resolves every file to a URL the app serves. `loadPatchSvg` fetches a
patch and its shared parts in parallel, joins them, and checks the result against the atlas's SHA-256:

```js
import { LIBRARY, orgsBySector, findPatch, loadPatchSvg } from 'patcher/library'

for (const { sector, orgs } of orgsBySector()) {
  for (const org of orgs) console.log(sector.name, org.name, org.patches.length)
}
const svgText = await loadPatchSvg(findPatch('S25-O01'))
```

Elsewhere, read `manifest.json` and join with `patcher/library/join` (`src/library-join.js`), plain JavaScript with no
DOM. `scripts/verify-library.mjs` shows how to do that from Node.
