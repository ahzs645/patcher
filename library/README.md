# Patch library

SVG patch art grouped by organization, for Patcher and for any app that embeds it.

```
library/
  orgs.json                   which organization each design belongs to (edit this)
  supplied/<package>/         better drawings supplied for some designs, with how they were made
  manifest.json               generated: sectors → organizations → patches, and the shared parts
  <org>/<id>.svg              the patch, with references to what it shares
  <org>/previews/<id>.webp    a small preview
  shared/<name>-<hash>.svg    a shared block: a crest or coat of arms several patches carry
  shared/paths-<hash>.json    shared path outlines, bundled by the patches that use them
```

Everything except `orgs.json`, `supplied/` and this file is generated by `npm run library:import`. Don't edit it by
hand, because the next import replaces it.

## Where the patches come from

The **BC Forestry Patch Atlas** snapshot: the atlas site's own "Entire codebase" ZIP, shared on
[Google Drive](https://drive.google.com/file/d/1FttYbiCfmrQW4TbvcDD7lpVG9Y-gRzs4/view). The import reads its
277 reconstructions (`dist/assets/reconstructions.json` plus each SVG and WebP preview) and nothing else.
`orgs.json` keeps 169 of them. 27 of those give way to supplied drawings of the same designs (below): 25
Forest Service and Wildfire Service ovals to PofBC's, and the two Forest Service / Parks ovals; 5 draw the
same design as another. With the 31 supplied variants, that leaves 154 patches and 14 badges. It leaves out
108, which `manifest.json` lists under `excluded` with the reason for each: the Province's identity (ministry
lockups, arms, programme marks), BC Timber Sales, the corporate logos of BC Hydro, BC Transit and ICBC,
the atlas's signs, decals, prevention cards, printed emblems and seals, and two fragments too small to
identify. It
does not read the source photographs, the template library or the registers. `manifest.json` records the
snapshot's SHA-256, and every patch keeps its atlas id, medium, quality, limitations and a link to its
source photograph.

They are reference-based vector reconstructions, not authenticated issue artwork. Fonts, thread colours and
fine embroidered detail are interpreted. Each patch's `limitations` says what is uncertain.

## Refreshing it

```bash
npm run library:import                         # downloads the snapshot (cached in .cache/)
npm run library:import -- --zip path/to.zip    # or use a copy you already have
npm run library:import -- --drive <id or URL>  # or a newer snapshot on Drive
```

Behind an HTTP proxy, prefix the command with `NODE_USE_ENV_PROXY=1`. The import refuses any SVG that has
scripts, event handlers, `foreignObject` or external references. It lists any design that no organization
claims, which are filed under `unsorted`.

## Shared parts

The drawings repeat a lot. The Conservation Officer Service crest (4.8 MB) is in three patches, and
the modern coat of arms is in sixteen. The same outlines also come back recoloured or moved. So the
import stores each repeated thing once, and the library is 8 MB instead of 29 MB:

- **Blocks.** When the same bytes sit inside a `<g>` in two or more places, they move to
  `shared/<name>-<hash>.svg`. The `<g>` stays in each patch with a placeholder,
  `<g data-shared="ID"/>`, inside it. A block can hold other blocks.
- **Path outlines.** A long `d="…"` that recurs with other colours or positions moves to a JSON
  bundle, and the attribute becomes `d="@ID"`. Outlines are bundled by exactly the patches that use
  them, and only when that group shares at least 4 KB. A patch therefore never downloads outlines it
  doesn't draw: opening one costs at most 3% more than its original file, in 1 request (median) to
  7 (max). Shared crests then come from cache.

Only exact bytes move. Joining a patch with its parts (`src/library-join.js`) gives back the atlas's
file byte for byte. The manifest records each patch's SHA-256 (the atlas's own `vectorSha256`) and the
blocks and bundles it needs, so a loader can fetch them all at once.

Every import ends by joining every design back from disk and comparing them with the snapshot. To
check again at any time:

```bash
npm run library:verify             # joined patches against the manifest's SHA-256
npm run library:verify -- --source # and file by file against the atlas snapshot
```

A stored `<org>/<id>.svg` is not the whole drawing on its own, so don't serve it directly. Load it with
`loadPatchSvg` (below), or join it with `joinSvg`.

## Collections, and what is left out

`orgs.json` has two more lists before the organizations:

- `collections`: **patches**, and **badges** (metal and leather, by medium). Badges are marked
  `"hidden": true`, so the apps leave them out of their menus for now. They are still in the library,
  and `?patch=<id>` still opens one.
- `exclude`: atlas designs to leave out, by id, with a reason. An organization can also carry
  `"exclude": "<reason>"`, which leaves out everything filed under it (Province of British Columbia,
  BC Timber Sales, BC Transit, ICBC, …).

To bring something back, delete its rule and re-import.

`relabel` gives a design a label of its own where the atlas's was wrong or left it unresolved, with a note
that joins its limitations (S56-O36 is the Justice Institute's bridge roundel; S48-O01 the Forest Service
evergreen emblem). Moving a design to another organization is a `family` rule like any other.

The atlas also has an entry per photograph a design was seen in, each fitted to its photograph, so
the same patch can come out several times (the Parks scenic arch four times). The import merges
entries that draw exactly the same thing, differing only in the canvas and the placement transform
directly inside it. It keeps the one from the largest photo crop, under the group's most common
label, and records the others in `merged` and every photograph in the patch's `sightings`. The
verifier checks each merged entry against the patch it went into.

A composed drawing is rebuilt by running its `compose.mjs`, then re-importing. Each replaced patch
records the supplied file and the atlas drawing's SHA-256 (`replaced`), and the verifier checks the

since it was replaced. Merged repeat photographs of a replaced design still group by the atlas's
drawing.

## Designs supplied with their variants

`consolidate` goes further than `replace`: it puts a supplied design, with all its variants, in the place of
several atlas entries. Each variant is a patch of its own with its own id, and lists the atlas entries it
takes the place of (`atlas`). Those are left out of the library and recorded in the manifest's `absorbed`,
and the variant carries their photographs. A variant that lists none is a colourway no photograph shows.
The group is one card, as below.

The Forest Service and Wildfire Service ovals are consolidated this way, into PofBC's own drawings of them
(Internal Logos → Forests), in `supplied/pofbc-forest-ovals/`:

| Card | Variants | Takes the place of |
|---|---|---|
| Forest Service tree oval | Full colour, Black & white, Forest green, White on green, Black & gold, Navy & gold, Wildfire Management (colour and black), Fire Control, Airtanker Operations | R22, R12, R21, R20, R11, R01 |
| British Columbia / Forests wildlife oval | Full colour, Black & white, Forest green, White on green, Wildfire Service | R15, R24, R13, R14, R23 |
| Forests, Lands and Natural Resource Operations wildlife oval | Full colour, Black & white, Forest green, White on green, Wildfire Service, Ministry of Forests | R16, R17, R18, S43, S58-O05 |
| Forest Service yellow-sky oval | Green, Cream, Dark | S05, S54, S04 |
| Forest Service green and gold oval | Full colour, Light band, Black & gold, Black & white | S47, S39, S35, S46, S24-O04, S42 |

The first three come from the Forest Oval engine PofBC vendors. `capture.mjs` renders each variant in a
browser from a PofBC dev server, as PofBC's Internal Logos view does, and outlines every letter from the
font the page used, so the files need no fonts. It also sets two wordings the presets lack, FIRE CONTROL and
Ministry of Forests, through the engine's own content fields. `drawings.mjs` copies the yellow-sky and
green-and-gold drawings from PofBC and makes the recolours. After running either, re-import.

The Forest Service / British Columbia / Parks tree oval is consolidated the same way, into two supplied vector
packages kept in `supplied/forest-service-parks-oval/` (see its README): Cream backing and Without backing
(R19, S26) from the first, and Bright gold, a second reconstruction from another image.

`findPatch` follows an absorbed id to its variant (and a merged one to its patch), so old links such as
`?patch=R22-O01` still open.

## Variants

`variants` shows related atlas designs as one card with a switch between them. Each group has an id, a card
label, and its members in order (the first is the card):

The Forest Service shoulder emblem (S44-O01, S56-O52) and the Conservation Officer lower rockers (MC19-O02,
MC20-O02) are grouped this way too.

```json
{ "id": "parks-scenic-arch", "label": "British Columbia / Parks — scenic arch",
  "members": [{ "id": "S30-O04", "name": "Parks" }, { "id": "S27-O04", "name": "Parks · Ranger" }] }
```

Every outline two variants draw goes into the group's own bundle, `shared/paths-variants-<id>.json`,
however small it is. Only the variants point into it, so other patches never fetch it. In code,
`variantsOf(patch)` gives a design's group and members, `isCard` and `cardOf` pick the card, and
`cardLabel` gives the card's label.

## Grouping by organization

The atlas's own `affiliation` is coarse: half the designs are "Other". `orgs.json` splits them into
organizations (BC Sheriff Service, BC Corrections, Highways and Motor Vehicles, BC Hydro, …) and groups
those into sectors. Organizations are tried in order and the first match wins:

```json
{ "id": "bc-sheriff-service", "name": "BC Sheriff Service", "sector": "justice",
  "match": { "family": ["^sheriff", "^deputy-sheriff-"] } }
```

`family` and `label` are case-insensitive regular expressions tested against the atlas design. `affiliation`
matches the atlas's affiliation exactly. Put specific rules above broad ones (BC Wildfire Service sits above
the catch-all `"affiliation": ["Forestry"]`). Then re-import.

## Using it from code

In a Vite app, `patcher/library` resolves every file to a URL the app serves. `loadPatchSvg` fetches a
patch and its shared parts in parallel, joins them, and checks the result against the atlas's SHA-256:

```js
import { LIBRARY, orgsBySector, findPatch, loadPatchSvg } from 'patcher/library'

for (const { sector, orgs } of orgsBySector()) {
  for (const org of orgs) console.log(sector.name, org.name, org.patches.length)
}
const svgText = await loadPatchSvg(findPatch('S25-O01'))
```

Elsewhere, read `manifest.json` and join with `patcher/library/join` (`src/library-join.js`), plain JavaScript with no
DOM. `scripts/verify-library.mjs` shows how to do that from Node.
